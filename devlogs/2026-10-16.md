### Bug: C: subdirectories returned garbage / Erc 668 / Erc 224
Symptoms, in order, while trying disk layouts:
1. 16×63 geometry, partition at LBA 63: `dir C:\` worked, but `dir C:\MSAMPLES` printed file data (ASM source)
   as directory entries, then Erc 668 (`ErcBadCmd`, IDE abort).
2. 16×17 geometry, partition at LBA 17: `dir C:\` was empty, and subdirectories gave Erc 224 (`ErcNoMatch`).

Diagnosis with QEMU tracing (`run.sh -trace ide_ioport_write -trace ide_sector_read -D /tmp/ide.log`):
- `dir C:\` read **sector 491**, but the root is at **474** (17 + 1 + 2×228). The CHS registers written were
  C=1 H=12 S=16, which is LBA 474 converted with **15 heads**, while the disk (and QEMU) has 16.
- The driver's `SET_PARAMS` (0x91) wrote Device/Head `0xAE`, i.e. 15 heads. With a 15-head disk it wrote `0xAD`
  (14 heads), so the driver is always one head short.
- Cause: `OSSOURCE/FSYS.C:579` `PDrvs[d].nHeads = partab[i].HeadEnd;`. HeadEnd is the highest head *index*
  (heads − 1), not the count. The source's `SetDriveGeometry` later overrides it with `ReadCMOS(0x1d)`
  ("fix for 3 gig hard disk"), but **the shipped `MMSYS/MMURTL.RUN` doesn't have that override**. This is
  another case of the binary not matching the source.
- Second factor: `HARDIDE.C` starts with a hardcoded 16×17 geometry, and `read_PE → GetBSInfo` reads the partition
  boot sector with it before learning the real geometry. Disks with 63 sectors/track break that first read.

Fix (tools only, original files untouched): `tools/boot32/mkhdd.sh`
- Classic geometry 16 heads × 17 sectors × 216 cylinders (~28.7 MB), with the partition at LBA 17 (CHS 0/1/1).
- MBR HeadEnd is written as `heads` (16) instead of 15, to match what this binary expects. mtools and QEMU only
  use the LBA fields.
- `run.sh` passes the same geometry to QEMU (`cyls=216,heads=16,secs=17`).

Result: Monitor shows `C: Heads 16, Sec/Trk 17, ... FAT16`. `dir C:\` lists `MMURTL` (label), `MMSYS` and
`MSAMPLES`, and `dir C:\MSAMPLES` lists all sample directories (paged with "ESC to cancel").

Note for the port: the 64-bit FS/IDE code must take geometry from the drive (IDENTIFY) or use LBA, never from
partition-table CHS fields.

## M1 — Hello, long mode (branch `m1-longmode-boot`)

Resumed after the pause. Goal: GRUB boots a 64-bit DOORS kernel that prints a banner.

### What was built (`port64/`)
- `boot/boot.asm`:
  - Multiboot2 header and 32-bit `_start`, with checks for the MB2 magic, CPUID and long mode. On error it
    prints `DOORS boot error: M/C/L` on VGA.
  - Boot page tables: the first 1 GiB in 2 MiB pages, mapped at 0 (identity) and at `0xFFFFFFFF80000000`
    (PML4[511] → PDPT[510]).
  - PAE, EFER.LME and PG on, then a minimal 64-bit GDT and a far jump to 64-bit code.
  - Loads the higher-half kernel stack (16 KB, `.bss`) and calls `kmain(magic, mbi)`.
- `linker.ld`: `.boot*` at physical 1 MiB; the rest at `KERNEL_VMA + phys`, loaded right after `.boot` (AT()).
- `drivers/serial.c` (COM1 115200 8N1), `drivers/vga.c` (80×25 TTY, scrolling, hardware cursor),
  `kernel/console.c` (`kprintf` to both, `panic`), `kernel/multiboot2.c` (loader name, cmdline, memory map),
  `kernel/main.c` (banner, boot info, CPU state, `DOORS: M1 OK`, isa-debug-exit when cmdline has `test`).
- `include/doors/`: `types.h` (MMURTL-style U8…S64, `erc_t`, `PHYS_TO_VIRT`), `x86.h`, `console.h`,
  `multiboot2.h`.
- `Makefile`: `make`, `run`, `debug`, `test`, `clean`, and `QEMU_EXTRA`. `grub/grub.cfg` takes the kernel
  cmdline from a template (the test ISO passes `test`).

### Bugs hit while building
- I first declared `kernel_stack_top` in C as a pointer variable, while `boot.asm` used it as a label (`mov
  rsp, kernel_stack_top` would load the variable's address). Fixed by defining the stack in `boot.asm`'s `.bss`.

### Results
- Compiles cleanly with `-Wall -Wextra -Werror`. `grub-file --is-x86-multiboot2` passes. The ELF has `.boot` at
  0x100000 and `.text` at 0xFFFFFFFF80106000 (phys 0x106000); the kernel is 28 KB.
- `make test`: **TEST PASS: DOORS: M1 OK** (QEMU exit 33). Serial log shows GRUB 2.06, 6 memory-map entries,
  255 MB usable (QEMU -m 256M), `CR0=80000011 CR3=101000 CR4=20 EFER=500` (LME+LMA).
- `make run` in a WSLg window shows the same output (read back with `qscreen.py --sock /tmp/doors.mon`).
- `-d int,cpu_reset`: no exceptions or interrupts logged during boot (the 2 resets are QEMU power-on).
  That one-off run exited with status 0 instead of 33; `make test` gets 33 consistently and is the
  authoritative check.

### Decisions
- Toolchain: Ubuntu's own x86-64 `gcc` with `-ffreestanding -mcmodel=kernel -mno-red-zone

  kernel and saves building a toolchain. Revisit if libgcc or host-header issues appear.
- Header directory is `include/doors/` (was `include/mmurtl/` in the plan).
- The full 64-bit GDT (user segments + TSS) moves to M2, where the TSS is needed for IST stacks.

## M2 — Interrupts & time (branch `m2-interrupts`)

### What was built (`port64/`)
- `arch/x86_64/gdt.c`: the full 64-bit GDT — kernel code/data (0x08/0x10), user 32-bit placeholder / data /
  64-bit code (0x18/0x20/0x28, ordered for SYSRET with STAR[63:48]=0x18), and a TSS at 0x30. The TSS has RSP0 =
  kernel stack, IST1 = 8 KB #DF stack, IST2 = 8 KB NMI/#MC stack, and no I/O bitmap. `gdt_load` (isr.asm)
  reloads the segments, does `ltr`, and reloads CS with `retfq`.
- `arch/x86_64/isr.asm`: 256 stubs generated with NASM `%rep`. A dummy error code is pushed where the CPU
  doesn't (error codes on 8, 10-14, 17, 21, 29, 30). `isr_common` saves all GPRs into `struct regs` and calls
  `isr_dispatch`. Frame size 176 bytes keeps the stack 16-byte aligned at the call.
- `arch/x86_64/idt.c`: 64-bit interrupt gates (IST on 2/8/18, DPL 3 on vector 3 for later user-mode `int3`),
  a handler table, IRQ dispatch with EOI, and `dump_regs` (GPRs, RIP/CS/SS/RFLAGS/ERR, CR2/CR3). An unhandled
  exception gives a register dump + panic.
- `arch/x86_64/pic.c`: 8259 pair remapped to 0x20-0x2F, all masked except the cascade line, `pic_unmask`,
  `pic_eoi`, spurious IRQ 7/15 detection (ISR register; for 15 the master still gets an EOI).
- `arch/x86_64/pit.c`: channel 0, mode 3, 100 Hz (divisor 11932). `timer_ticks`, `timer_sleep`. Updates the
  status-bar `Tick:` every 10 ticks.
- `drivers/keyboard.c`: IRQ1, scan code set 1 → ASCII with Shift/Caps, 64-byte ring buffer, `kbd_getc`.
- `drivers/vga.c`: row 0 is now a fixed status bar (`vga_set_title`, `vga_status_tick`); text scrolls in
  rows 1-24.
- `kernel/string.c` + `include/doors/string.h`: memcpy/memmove/memset/memcmp/strlen/strcmp/strncmp
  (freestanding; GCC can emit these calls itself).
- `kernel/main.c`: bring-up order GDT → IDT → PIC → PIT → keyboard → `sti`. Interactive line monitor with
  `help`, `ticks`, `int3`, `pf`, `div0`.
- `kernel/selftest.c` (cmdline `test`), run in this order:
  1. Timer: count PIT ticks across one CMOS RTC second (must be 90-110).
  2. Two `int3`: the handler must run twice and execution must resume.
  3. Keyboard: prints "M2: type doors", reads a line, and expects "doors".
  4. A write to unmapped 0xdead0000: the #PF handler dumps registers, checks CR2 and the write bit in the
     error code, prints `DOORS: M2 OK`, and exits QEMU.
  A panic in test mode exits QEMU with status 35 instead of hanging.
- `tools/qemu_test.py` (now behind `make test`): boots the test ISO headless with a monitor socket and
  isa-debug-exit, types `--send` text when a trigger line appears in the serial log, and passes on exit status 33
  plus all `--expect` lines. It reuses `text_keys` from `tools/boot32/qscreen.py`.

- Interactive window: `help`, `ticks` ("Tick: 978 (9.78 s …)"), `int3` (handled, "back from the breakpoint

## M3 — Memory (branch `m3-memory`)

### What was built (`port64/`)
- `kernel/pmm.c`: physical page bitmap from the Multiboot2 map (like MMURTL's PAM, but over all RAM). It is
  placed in free RAM above the kernel and the MBI, below 1 GiB (the boot map limit). Reserved: < 1 MB, the
  kernel image, the bitmap and the MBI. Ordinary allocations start searching at 16 MB, so the DMA zone stays
  free. `pmm_alloc_contig(n, limit)` serves DMA. Pages are zeroed. QEMU 256 MB: 65407 usable pages, bitmap 8 KB.
- `kernel/vmm.c`: the kernel's own 4-level tables:
  - Direct map of all RAM at `0xFFFF800000000000` (2 MiB pages, RW+NX).
  - Kernel image in 4 KB pages: .text RX, .rodata R+NX, .data/.bss RW+NX.
  - The guard page under the 16 KB kernel stack is left unmapped.
  - `EFER.NXE` and `CR0.WP` are set. All kernel-half PDPTs (PML4 256-511) are created up front, so every
    address space can share them by copying 256 PML4 entries.
  - API: `vmm_map`/`unmap`/`translate`/`find_free`, `vmm_space_create`/`destroy`/`switch`, and
    `job_space` (temporary job → space table until M6).
- `kernel/mem.c`: the MMURTL calls with their names, parameter order and error codes: `AllocOSPage`
  (OS region `0xFFFFC00000000000`), `AllocPage` (current job, from `0x40000000` as in MMURTL), `AllocDMAPage`
  (contiguous < 16 MB, returns the physical address), `DeAllocPage` (frees as many valid pages as it can,
  never frees aliases; `ErcBadLinAdd`/`ErcShortMem`), `QueryPages`, `GetPhyAdd`, `AliasMem` (maps another job's
  pages into the current job with the AVL alias bit; same job → returns pMem), `DeAliasMem` (`ErcBadAlias` for
  a non-alias). Types widened: pointers, byte counts and physical addresses are 64-bit.
- `arch/x86_64/probe.asm` + `fault_fixup` in idt.c: `probe_read`/`probe_write` return false on #PF/#GP via
  a fixup table (as Linux's exception table does). This is the basis for checking user pointers in M6.
- `boot.asm`: guard page before `kernel_stack`. `linker.ld`: `_text_*`/`_rodata_*` symbols, .rodata
  padded to 4 KB.
- `multiboot2.c`: cmdline and loader name are copied out, because the boot mapping disappears.
- Interactive `mem` command: QueryPages plus an AllocOSPage/DeAllocPage round trip.

## M4 — Tasks (branch `m4-tasks`)

### MMURTL semantics checked first (KERNEL.ASM, TMRCODE.ASM)
- 32 ready queues, scanned from priority 0, so **0 is the highest**.
- IntTimer: after the running task has had **3 ticks (30 ms)**, switch if a queued task's priority is
  **equal or higher** (`CMP DL,[EAX+Priority]` / `JC`). It sends EndOfIRQ *before* the task switch.
- `Sleep` = a timer block that ISendMsg's the task's own exchange (TSS_Exch) when it reaches zero.
- `NewTask(JobNum, CodeSeg, Priority, fDebug, Exch, ESP, EIP)`: OS tasks (CodeSeg 8) use a preallocated
  stack. `SpawnTask(pEntry, dPriority, fDebug, pStack, fOSCode)`. `SetPriority(bPriority)`,
  `GetPriority(pbPriorityRet)`.

### What was built (`port64/`)
- `include/doors/task.h`, `kernel/sched.c`:
  - `struct task` holds the TSS.INC OS fields (Tid, job, priority, exchange, debug flag, next) plus the
    saved RSP, address space, kernel stack and stats. 256 slots.
  - Each task gets a 16 KB kernel stack in a 32 KB slot at `STACK_BASE` (0xFFFFC08000000000), with an
    unmapped guard page below it.
  - Ready queue: a FIFO per priority. The idle task is never queued and runs only when nothing else can.
  - Preemption follows the MMURTL rule above, plus one **deliberate change**: a task that becomes ready with a
    **strictly higher** priority (woken or spawned) runs immediately rather than at the next 30 ms check.
    That gives better real-time latency; equal priorities still round-robin on the 30 ms slice.
  - `Sleep` uses a sleep list checked by the timer. It becomes timer blocks + exchanges in M5, as in MMURTL.
  - Exited tasks go on a zombie list and their stacks are freed by the next task that runs ("reap").
  - Calls: `NewTask` (kernel CodeSeg only until M6, else ErcNotSupported 227), `SpawnTask` (fOSCode only;
    pStack ignored, kernel tasks always get a guarded stack), `SetPriority`/`GetPriority` (ErcBadPriority 50),
    `Sleep`, `GetTimerTick` (64-bit), `task_create` (internal, with an argument).
- `arch/x86_64/switch.asm`: `switch_to` (callee-saved regs + RSP) and `task_trampoline` (new task: reap, `sti`,
  `entry(arg)`, `task_exit`). The initial frame leaves RSP 16-byte aligned at the first call.
- `idt.c`: IRQs are now EOI'd **before** the handler, since the timer handler may switch tasks (MMURTL did the same).
- `gdt.c`: `tss_set_rsp0` on every switch. `vmm_space_switch` records the space in the current task.
- Locking: `irq_save`/`irq_restore` moved to `x86.h`. The page allocator and every MMURTL memory call are
  wrapped (`*_nolock` + locked public entry), because tasks can now preempt each other inside them.
- `kmain` becomes task 1 (priority 20). The interactive monitor waits with `Sleep(1)` instead of `hlt`, so
  lower priorities run. New commands: `tasks` (list + switches/slices/idle ticks) and `spin` (two busy tasks for 3 s).

## M5 — Messaging (branch `m5-messaging`)

### MMURTL semantics checked first (KERNEL.ASM, RQB.INC, MOSEDF.INC, SVCCODE.ASM, TMRCODE.ASM)
- Exchange = one queue that holds either messages (link blocks) or waiting tasks (`fEMsg` flag). FIFO.
- Message = two DWORDs. Request → service gets `(pRqBlk, 0)`. Respond → client gets `(RqHandle, status)`.
  Timer → `(-1, -1)`.
- SendMsg/Request/Respond: if a task waits, it gets the LB (`pLBRet`), goes on the ready queue, the sender is
  queued behind it and the highest one runs. So **equal or higher** priority receivers run at once.
  ISendMsg never switches.
- WaitMsg on a **request** LB: AliasMem pData1/pData2 (with cb ≠ 0, non-NULL) from `RqOwnerJob` into the
  receiving job, **writing the alias pointers into the RqBlk**. Respond DeAliasMem's them, disposes the RqBlk,
  then sends the response. `ErcOwnerAbort` as status: just free the RqBlk. MoveRequest: only to an exchange
  the caller's job owns; the LB type REQLBA means "already aliased".
- DeAllocExch: owner or the OS (Monitor JCB) only; frees queued LBs/RQBs.
- Sleep: timer block → ISendMsg to the task's TSS_Exch, then WaitMsg on it. Alarm(exch, n), KillAlarm(exch).
- **`__Request` dData2: confirmed bug.** The routine's own header lists `dData2 [EBP+12]`, but the code does
  `MOV EAX,[EBP+20] ;Get dData2`, which is dData0's slot. Services always received dData0 in dData2.

### What was built (`port64/`)
- `include/doors/erc.h`: every MMURTL kernel/memory error code in one place (mem.h, task.h now include it).
- `include/doors/msg.h`: API, `struct RqBlk` (RQB.INC widened: pointers/sizes 64-bit; codes, exchanges and
  dData0-2 32-bit; private fields for the original pointers and the aliasing job).
- `kernel/msg.c`:
  - Exchanges (1024; 0 = "none") and link blocks (4096), both from AllocOSPage.
  - `deliver`/`msg_post` implement MMURTL's hand-to-waiter-or-queue.
  - AllocExch/DeAllocExch (waiting tasks wake up with ErcNotAlloc — DOORS change), GetTSSExch, SendMsg,
    ISendMsg, WaitMsg (blocks via `sched_block`), CheckMsg.
  - Timer blocks (64) with Alarm/KillAlarm/`msg_timer_tick`; **Sleep = Alarm on own exchange + WaitMsg**,
    which replaces M4's sleep list.
- `kernel/rqb.c`:
  - Request blocks (256) and the service registry (64 names).
  - `rqb_received` aliases buffers into the service's job (skipped when both sides share an address space).
  - Request (**dData2 stored correctly**), Respond (validates the handle → ErcNotRqBlk; de-aliases),
    MoveRequest (ErcNotOwner for another job's exchange), RegisterSvc (re-registering moves the name),
    UnRegisterSvc.
- `kernel/sched.c`:
  - `sched_block`, `sched_wake(t, may_switch)` (MMURTL's equal-or-higher rule), `sched_irq_exit` (called
    after every IRQ handler: strictly higher priority runs at once — the M4 policy, now also for tasks
    woken by ISendMsg).
  - Every task gets its own exchange at creation (freed at reap); NewTask's Exch parameter replaces it.
- `drivers/keyboard.c`: `kbd_set_exch` — keys go out as `ISendMsg(exch, key, 0)` instead of into the buffer.
  The interactive monitor now **blocks in WaitMsg** (12 switches in ~6 s idle vs. polling every 10 ms).
  `tasks` also shows free exchanges/LBs/RqBlks, timers and services.

### Self-tests (all pass, 3 runs; M1-M4 unchanged and still passing)
- `M5: exchanges ok`: FIFO of 3 messages, CheckMsg/WaitMsg, ErcNoMsg, ErcOutOfRange (0 and nEXCH),
  ErcNotAlloc after DeAllocExch, a queued message freed by DeAllocExch.
- `M5: WaitMsg/SendMsg ok`: receivers at priority 10 and 20 run before SendMsg returns; one at 30 runs only
  after kmain sleeps.
- `M5: ping-pong ok`: **10000 round trips, 20000 task switches, ~1-2 ticks**, every reply correct.
- `M5: Alarm/KillAlarm ok`: Alarm(5) fired after 5 ticks; a killed alarm never fires; ErcOutOfRange on exch 0.
- `M5: keyboard ISendMsg ok`: "msg" typed by the test runner arrives as messages from the IRQ, with an Alarm
  on the same exchange as the timeout.
- `M5: Request/Respond ok`: NUMBERS service (like MSAMPLES/SERVICE): numbers 0, 1; **dData0-2 = 7,8,9**;
  ErcBadSvcCode status; ErcNoSuchSvc; ErcNotRqBlk for a bogus handle; shutdown + UnRegisterSvc.
- `M5: cross-job Request ok`:
  - The job 2 client (own address space, buffer from AllocPage) asks the job 3 UPCASE service.
  - The service checks that MoveRequest to a job 1 exchange gives ErcNotOwner, then moves the request
    to its worker.
  - The worker sees the client's buffer through an alias (same physical page via GetPhyAdd), writes the
    upper-cased text into pData2, Responds, and finds the alias gone afterwards.
  - The client reads "DOORS MESSAGING".
- `M5: no leaks`: exchanges, link blocks, request blocks, services, timers and pages back to their start
  values after both address spaces are destroyed.

### Deliberate differences from MMURTL (all documented in the code)
- dData2 bug fixed; Respond/MoveRequest validate the handle; DeAllocExch wakes waiters with ErcNotAlloc;
  a strictly higher-priority task woken by ISendMsg runs at IRQ exit; messages are 2×U64; pools are bigger.

### Not yet

- Console output from several tasks isn't serialised (a console lock or a video service comes later).

## M6 — User mode, system calls, jobs (branch `m6-usermode`)

### MMURTL facts used
- `MPUBLICS.ASM`: 110 call gates, selectors 40h..3A8h, 8 bytes apart → call number = (selector − 40h)/8.
- MJOB.H / MVID.H signatures: `LoadNewJob(pFileName, cbFileName, pJobNumRet)`, `ExitJob(dError)`,
  `KillJob(JobNum)`, `SetJobName`, `GetJobNum`, `GetCmdLine(pCmdRet, pdcbCmdRet)`,
  `TTYOut(pTextOut, ddTextOut, ddAttrib)`. Errors ErcBadRunFile 74, ErcNoSuchFile 203, ErcBadCallGate 49
  (uninitialised gate).

### What was built
- `include/doors/syscalls.def` generated from MPUBLICS.ASM by `tools/gen_syscalls.sh` (X-macro, never renumber).
- `arch/x86_64/syscall.asm`:
  - SYSCALL entry: user RSP saved with interrupts masked (FMASK), switch to `syscall_kstack` (updated on
    every task switch), `syscall_dispatch(rax, rdi)`; scratch registers cleared; SYSRET.
  - `enter_user`: iretq to ring 3 with clean registers.
  - ABI: RAX = number, RDI = user array of U64 args in MMURTL order.
- `arch/x86_64/uaccess.asm`: `user_copy` (rep movsb) with a fixup that returns the uncopied byte count;
  `fault_fixup` now scans the probe and uaccess tables, kernel RIPs only.
- `kernel/syscall.c`:
  - STAR/LSTAR/FMASK + EFER.SCE.
  - Every pointer checked with `urange` (≥ 4 KB, < USER_TOP) and copied with fixups.
  - Request's pData1/pData2 must be user addresses: otherwise AliasMem, which passes kernel-half
    addresses through unchanged, would let a service write kernel memory.
  - RegisterSvc only on the caller's own exchange. SpawnTask from ring 3 makes user tasks only.
  - Request handles are translated to and from `RQB_UBASE`.
  - About 35 calls are implemented; the rest (port I/O, IRQs, AllocOSPage, ISendMsg, NewTask, video, file
    system) return ErcBadCallGate.
- FPU/SSE (`sched.c`): CR0.MP on, EM/TS off; CR4.OSFXSR|OSXMMEXCPT; a clean FXSAVE template captured at
  boot; a 512-byte area per task; eager fxsave/fxrstor on every switch.
- Request blocks for user services (`rqb.c`): the pool is mapped a second time, read-only + user, at
  `RQB_UBASE`, so ring-3 services read RqBlk fields as MMURTL services did. `vmm_map` now propagates the
  U bit down the table levels for such kernel-half user pages. Trade-off: any job can read (not write)
  any request block. MMURTL had no protection here at all; a per-service copy could replace it later.
- `kernel/job.c` + `include/doors/job.h`:
  - Job control blocks; jobs 1 = OS, 2 reserved (debugger, as in MMURTL), user jobs from 3.
  - ELF64 loader: static ET_EXEC, PT_LOAD segments mapped with their own permissions
    (R+X / R / RW+NX), file bytes copied, bss zero; 64 KB user stack at 0x7FFFFFFF0000 with a guard.
  - `LoadNewJob` finds programs among the **GRUB boot modules** (no file system until M7).
  - Teardown order: kill tasks → orphan/fail requests → unregister services → free exchanges →
    destroy the address space → "Job number N terminated. Error: E" (the MMURTL Monitor message).
  - `job_fault`: a CPU exception in ring 3 ends that job with error 1000 + vector.
  - `INITIAL.JOB` (a boot module): programs started at boot.
- Teardown support:
  - `sched_kill_job` (off the ready queue / exchange wait queue → zombies).
  - `exch_remove_waiter`, `exch_free_job`.
  - `rqb_job_gone`: requests from the dying job become orphans and the services' aliases of its pages are
    unmapped at once; requests it was serving are failed back with ErcNoSuchSvc.
  - Queued requests on a freed exchange are failed back instead of dropped. `svc_job_gone`.
- Multiboot2 modules parsed (name + args); the pmm reserves them and keeps its bitmap clear of them.
- Console: kprintf and TTYOut run with interrupts off, so lines from different jobs don't interleave.
  kprintf gained `%.*s`.
- User side (`port64/user/`):
  - `user.ld` with explicit PHDRS. The first link used `ld -n`, which merged everything into one RWE
    segment; caught with readelf and fixed.
  - `crt0` (main → ExitJob(ret)); `doors.h` (MMURTL API names); `libdoors.c` (stubs via the .def, the
    CopyData/FillData/Compare helpers in the library, memcpy/memset/strlen, printf over TTYOut).
  - Programs: hello, badptr, fpu, upsvc, upcli, spinner. `INITIAL.JOB` starts hello on a normal boot.
- Makefile: builds the user programs and generates grub.cfg with one `module2` per program plus
  INITIAL.JOB (the old grub/grub.cfg template is gone).
- Monitor: `run NAME`, `jobs`, `kill N`; INITIAL.JOB processed at boot.

### Self-tests (all pass, 3 runs; M1-M5 unchanged)
- `M6: hello ok`: ring-3 job 3; GetJobNum, GetTSSExch, GetCmdLine, AllocPage(2), QueryPages, Sleep(10)

## M7 — Disks and FAT (branch `m7-disks-fat`)

### MMURTL facts used (MDEVDRV.H, MFILES.H, MSTATUS.H, FSYS.C)
- `DeviceOp(dDevice, dOpNum, dLBA, dnBlocks, pData)`, `DeviceStat`, `DeviceInit`, `InitDevDr`; device 12/13 =
  hard disk 0/1.
- `OpenFile(pName, cbName, Mode, fStream, pdHandleRet)`, ModeRead 0 / ModeModify 1; a stream file uses
  ReadBytes/WriteBytes at the LFA; a block file uses ReadBlock/WriteBlock with 512-byte multiples;
  `DeleteFile(handle)`; `GetDirSector(path, cb, pSectorRet, sSectorRet, SectorNum)`; MMURTL's FS was a
  service task at priority 5.
- Error codes 200-231 (file system), 500-506 (devices). There is no "directory not empty" code, so DOORS
  adds ErcDirNotEmpty 232.

### What was built (`port64/`)
- `include/doors/blk.h`, `kernel/device.c`: device table; DeviceOp/DeviceStat/DeviceInit (64-bit LBA,
  bounds-checked, raw writes invalidate the cache).
- `drivers/ata.c`: ATA PIO, LBA48 (LBA28 fallback), size from IDENTIFY, model string, polled with
  timeouts, nIEN set, one kmutex per channel, ATAPI/SATA signatures skipped. Devices 12..15.
- `kmutex` (msg.c): an exchange holding one token message (lock = WaitMsg, unlock = ISendMsg). This is
  the MMURTL idiom for serialising.
- `kernel/bcache.c`: 1024 × 512-byte LRU write-through cache.
- `drivers/rtc.c`: CMOS clock (BCD/binary, 12/24 h, read until two passes agree).
- `kernel/vol.c`: MBR partitions, GPT behind a protective MBR, superfloppy FAT (checked before the MBR,
  so a boot sector's code isn't taken for partitions); letters from C:; Linux partitions recorded for M8.
- `kernel/fat.c` (≈ 950 lines): FAT12/16/32 by cluster count:
  - FAT12 entries that straddle a sector boundary; every FAT copy updated; FAT32 FSInfo marked unknown
    before the first change.
  - Directories: fixed root (12/16) or cluster chains that grow when full.
  - Names: VFAT long names (read with checksum checks; created with `NAME~N` aliases), case-insensitive
    lookup, `.`/`..` in paths.
  - Operations: create/remove/rename/move (a moved directory's `..` is rewritten), byte-exact read/write,
    grow/truncate with zero fill, RTC timestamps (`NOW()` macro, because GCC refuses `&` on packed
    fields), GetDirSector support, empty-directory check.
- `kernel/fsys.c`:
  - The FILESYS service (priority 5, as MMURTL's) with 128 open-file slots.
  - Sharing rules: readers share, a modifier is exclusive (ErcFileInUse). Handles belong to the job;
    a dead job's files are closed (`fsys_job_gone`).
  - The MMURTL calls are Request + WaitMsg wrappers. pData1 = path or data buffer, pData2 =
    `struct fs_req` (parameters + results).
- `kernel/syscall.c`: all 17 file calls for ring 3 (paths copied in, buffers range-checked and passed to
  the service through aliasing); `user/lib`: stubs + prototypes; new program `fsuser`.
- `job.c`: `LoadNewJob("C:\BIN\HELLO.ELF")` reads the file through the FILESYS calls into AllocOSPage memory.
  A name without a drive is still a boot module.
- Monitor: `vols`, `dir C:\PATH` (via GetDirSector, shows long names), `type C:\FILE`, `run C:\...`.
- `tools/mkdisk.py`: 96 MB test disk, MBR + FAT32/16/12 partitions made by `mkfs.fat`, files put with
  mtools (a long name, nested dirs, a 200000-byte multi-cluster file, BIN/HELLO.ELF).
  `tools/check_disk.py`: after the test, `fsck.fat -n` on each partition + mtools read-back of everything
  the kernel wrote. `qemu_test.py --disk`; `make test` = mkdisk + qemu_test + check_disk; `make run` keeps
  `build/disk.img`.

### Security bug found while writing fsuser
- A ring-3 program could pass a **read-only** page (its own rodata) as the buffer for ReadBytes. The
  FILESYS service (ring 0) would write through the read-only alias and take a #PF at an instruction with
  no fixup: **kernel panic** caused by a user program.
- Fix: MMURTL's request blocks already distinguish send buffers (first npSend) from receive buffers.
  `rqb_received` now checks that every page of a receive buffer is writable in the requester's space
  (else ErcBadLinAdd), and the file calls set npSend correctly (ReadBytes/ReadBlock/GetDirSector = 0).
  fsuser tests it.
- Remaining risk, noted: a requester could free a page while a service holds an alias of it (no page
  reference counts yet). MMURTL had the same window.

### Self-test fallout
- Two older leak checks assumed 0 registered services / 2 tasks. FILESYS is now a permanent service and
  task, so they compare against a baseline instead.
