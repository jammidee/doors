## ROADMAP 3.1: growable kernel tables, kernel heap (1.11.0)
- New `port64/kernel/gtable.c` / `include/doors/gtable.h`:
  - Each table has a 16 GiB slice at GT_BASE (PML4 387), and pages are mapped as it grows (`gt_grow`, interrupts off).
  - Entries never move. Code loops to `t->n` (the entries that exist), not to the ceiling.
  - Free counters count against the ceiling, so leak checks don't change when a table grows.
  - The RQB table is also mapped user-readable at RQB_UBASE, as before (uwin).
- Converted:
  - tasks (sched.c, grows by 64), exchanges (by 256) and link blocks (by 1024; msg.c), request blocks (rqb.c, by 64), open files (fsys.c, by 64);
  - the per-job tables together through `job_grow()` (job.c): jobs, address spaces (vmm.c), screens (video.c) and key buffers (kbdsvc.c).
  - Jobs 0–2 keep static screens, because vid_init runs before vmm_init.
  - Keyboard wake-up exchanges are made per job slot as the table grows, and they stay.
- New `kernel/kheap.c`: kmalloc/kfree with 8 size classes of 16..2048 bytes from AllocOSPage pages, whole pages above that. A 16-byte header with a magic number, so a bad or double free panics. `kheap_check` is in kcheck. Nothing uses it yet; it is there for drivers and the network stack.
- Bugs found by the new 1000-jobs test (`test_many_jobs`, selftest.c):
  - **Job numbers were never reused.** `job_end` leaves `used` set (the exit code stays readable), and LoadNewJob only took never-used slots, so every job used up a number. With 64 fixed slots the system had room for only 61 programs in all. Before 3.1 no test ran that many.
  - Fix: `free_slot()` (job.c) takes a never-used slot first, then the lowest `ended` slot with no tasks left; growing comes last. The new `ended` flag (job.h) is needed because a slot being built is `used && !alive` too.
  - `job_has_tasks()` (sched.c) reaps zombies first: back-to-back LoadNewJobs never switch tasks, so killed tasks would otherwise still be there.
  - **Boot modules were capped at 16, silently.** Adding `idle` (the 17th) dropped INITIAL.JOB, and `test_user_hello` failed with "a text file loaded as a program". Now MAX_BOOT_MODS = 64 (multiboot2.h), and any more are reported.
  - The second round of 1000 jobs still kept 1 page: a page table in the OS page region, kept for reuse, since the kernel stacks land at other addresses. A third round gives back exactly what it took, so the test takes its baseline after round 2.
- clang --analyze: `erc` in kbd_service_start could go uninitialized into panic() (kbdsvc.c:179); it is now initialized.
- New monitor command `tables` (gt_report and heap statistics). `tasks` loops to `task_limit()`.
- make test PASS (1000 jobs × 3 rounds in 2.4 s, tables at 1024 jobs, 1419 pages), CHECK_DISK PASS, make analyze PASS, make smoke PASS 25 / FAIL 0.
