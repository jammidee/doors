## ROADMAP step 1.2: deep extent trees on write (1.3.0)
- Replaced the depth-0/1-only `ext_add`/`ext_truncate` in port64/kernel/ext4.c ("extents: writing (any depth)").
  - `ext_ins` recurses down the index; leaves and index nodes split (`node_split`).
  - A full inode root moves into a new block one level down (`ext_grow`). The limit is depth 4 (`EXT_MAXDEPTH` 5). At depth 5 (the ext4 maximum, never seen in practice) writing gives `ErcBrokenFile`.
  - `ext_cut_tree` truncates at any depth and frees the nodes it empties.
  - The index child is always rewritten after recursing, because its first key may change.
- Test `test_deep_extents` (kernel/selftest.c) on G: (1K blocks, so 84 extents per leaf):
  - FRAG2.BIN is written as 400 one-block fragments, cut to 200, then grown to 480: a depth-2 tree.
  - FRAG3.BIN gets 400 fragments and is then deleted.
  - check_disk.py checks FRAG2's depth and extent count with `debugfs ex`, and that FRAG3 is gone. `e2fsck -fn G:` is clean.
- The first version used 1000/1200 fragments. That passed, but it ran past the 240 s test timeout, so it was cut to 400/480.
- Timing showed the journal was the bottleneck (timer ticks were printed around each test, now removed).
  - **Sector-granular transactions:** `tx_put` compares each 512-byte sector and sets a per-slot dirty mask. Slots with nothing dirty are dropped before logging. The checkpoint writes only the dirty sectors.
  - **jsb_write** keeps the jsb's first sector in memory (`jsb_sec`, `jsb0`, set in journal_mount) and rewrites only it.
  - Results: stress 99 → 63 s, htree 24 → 20 s, deep 33 → 26 s.
  - **Multi-sector writes:** new `bc_write_n` (kernel/bcache.c) sends n sectors as one `blk_io` command, so the ATA driver issues one write plus one FLUSH instead of n of each. `bwr` and each checkpoint run of dirty sectors use it.
  - Full `make test` now takes 2m18s.
- Results: `make test` PASS + CHECK_DISK PASS (both disks), `make powercut` 5/5 PASS, `make smoke` 24 PASS / 1 deferred.
- Version **1.3.0**.
  - Docs: CHANGELOG; devman 1, 6 (limits row), 10, 11 (limits row, which had still listed htree writes as missing); PORT64_PLAN ✅; PLAN M8b; ROADMAP 1.2 ✅; the ext4.c header.
  - ROADMAP 1.2 asked for 10,000 fragments. The test covers 480 every run, and 1,200 passed once. 10,000 is left until the disk path is faster.
