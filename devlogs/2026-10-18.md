## ROADMAP step 1.2: deep extent trees on write (1.3.0)
- Replaced the depth-0/1-only `ext_add`/`ext_truncate` in port64/kernel/ext4.c ("extents: writing (any depth)").
  - `ext_ins` recurses down the index; leaves and index nodes split (`node_split`).
  - A full inode root moves into a new block one level down (`ext_grow`). The limit is depth 4 (`EXT_MAXDEPTH` 5). At depth 5 (the ext4 maximum, never seen in practice) writing gives `ErcBrokenFile`.
  - `ext_cut_tree` truncates at any depth and frees the nodes it empties.
  - The index child is always rewritten after recursing, because its first key may change.
- Test `test_deep_extents` (kernel/selftest.c) on G: (1K blocks, so 84 extents per leaf):
  - FRAG2.BIN is written as 400 one-block fragments, cut to 200, then grown to 480: a depth-2 tree.
  - FRAG3.BIN gets 400 fragments and is then deleted.
  - check_disk.py checks FRAG2's depth and extent count with `debugfs ex`, and that FRAG3 is gone. `e2fsck -fn G:` is clean.
- The first version used 1000/1200 fragments. That passed, but it ran past the 240 s test timeout, so it was cut to 400/480.
- Timing showed the journal was the bottleneck (timer ticks were printed around each test, now removed).
  - **Sector-granular transactions:** `tx_put` compares each 512-byte sector and sets a per-slot dirty mask. Slots with nothing dirty are dropped before logging. The checkpoint writes only the dirty sectors.
  - **jsb_write** keeps the jsb's first sector in memory (`jsb_sec`, `jsb0`, set in journal_mount) and rewrites only it.
  - Results: stress 99 → 63 s, htree 24 → 20 s, deep 33 → 26 s.
  - **Multi-sector writes:** new `bc_write_n` (kernel/bcache.c) sends n sectors as one `blk_io` command, so the ATA driver issues one write plus one FLUSH instead of n of each. `bwr` and each checkpoint run of dirty sectors use it.
  - Full `make test` now takes 2m18s.
- Results: `make test` PASS + CHECK_DISK PASS (both disks), `make powercut` 5/5 PASS, `make smoke` 24 PASS / 1 deferred.
- Version **1.3.0**.
  - Docs: CHANGELOG; devman 1, 6 (limits row), 10, 11 (limits row, which had still listed htree writes as missing); PORT64_PLAN ✅; PLAN M8b; ROADMAP 1.2 ✅; the ext4.c header.

## ROADMAP step 1.3: journals with checksums (1.4.0)
- e2fsprogs 1.46.5 makes journals without checksums; 1.47 and Linux's mount (on metadata_csum volumes) set csum_v3. `debugfs jo -c` opens a journal with csum_v3 and writes checksummed transactions: an independent reference.
- port64/kernel/ext4.c, "journal" section:
  - `jsb_csum`, `jblk_csum` (block with a 4-byte field counted as zero), `jdata_csum` (seed, be32 transaction ID, the block as escaped in the journal), `jtag_csum_ok` (v3: 32 bits at tag+12, v2: low 16 at tag+4). Seed = crc32c(~0, journal UUID).
  - `struct ext4`: `jsb0[512]` became `jsb[1024]` (the superblock checksum covers 1024 bytes) plus `jseed`. `jsb_write` still writes only the first sector; s_checksum (0xFC) is in it.
  - `tx_commit`: descriptor capacity ends 4 bytes early, tag checksums, descriptor tail, commit `h_chksum[0]` at 16 (type/size 0, as Linux's v2/v3).
  - `jpass` scan pass checks commit, descriptor and revoke checksums and every logged block's tag; the first bad one ends the log (kprintf names it). The later passes stop at the scan's end, so nothing past it is replayed.
  - `journal_mount`: checksum type must be CRC32C (4), superblock checksum checked; `JI_WRITE` now includes v2/v3.
  - Fixed on the way: a csum_v3 tag's high block half was used without `64bit`; Linux ignores it then.
- Tests:
  - tools/mkdisk.py: F: gets `jo -c` and two transactions; the second rewrites CSUMBAD.TXT and mkdisk damages its logged block (journal block 5). `--plain-journal` keeps the old journal.
  - Makefile expect `ext4 on F: a block logged in transaction 2 has a bad checksum: the log ends there`; check_disk: CSUMBAD.TXT unchanged, F: journal still csum_v3/crc32c.
  - tools/powercut.py: even runs csum_v3, odd runs plain.
  - Control: after a `powercut stop=60` boot on csum_v3, e2fsck -fy replayed DOORS's transaction 61 cleanly; with one byte of DOORS's logged block changed it reported "JBD2: Invalid checksum recovering data block", so the clean replays do prove the checksums.
- Results: `make test` PASS + CHECK_DISK PASS (4m00s), `make powercut` 5/5 PASS (3 csum_v3, 2 plain), `make smoke` 24 PASS / 1 deferred. All passed on the first try.
