## ROADMAP step 1.5: FAT after a power cut (1.6.0)
- Started late on 2026-10-18, after 1.5.0 (fc0e610, tag v1.5.0, main fast-forwarded).
- Ground truth first: what fsck.fat 4.2 says. It reads the dirty flag from boot sector byte 65 (FAT32) / 37 (FAT12/16), bit 0, as Linux's fat driver writes it (primary boot sector only, so FAT32 also gets a harmless "differences with backup: 65:01/00" note). Lost clusters: "Reclaimed N unused clusters".
- kernel/fat.c:
  - `wr()` sets the dirty flag before the first write after mount (`set_dirty`, `state_off` only with the 0x28/0x29 extended signature). New `fat_unmount()` clears it, called with ext4_unmount from the monitor's `sync` (kernel/main.c), the end of selftest and pccheck. `was_dirty`: a volume dirty at mount stays dirty (Linux's fat_set_state does the same), so fsck still checks it.
  - `fat_check()`, at mount when the flag was set: a bitmap of owned clusters, directories from a queue (no recursion: 16 KB stack), every chain walked in fsck.fat's check_file order (free/bad entry -> "reaches a free cluster"; a file whose size already fits -> "chain is longer"; owned -> "shares clusters"; then "holds only N bytes"), then lost clusters and a FAT copy compare. Report only; 8.3 names in paths, as fsck prints them.
  - dir_walk and find_free stop at 65,536 entries (FAT's limit; a looped directory chain made them endless).
- What a DOORS crash can leave follows from its write order (grow-then-size, free-then-entry, mark-then-free, add-then-delete for rename, FAT 1 then FAT 2).
- kernel/powercut.c: `vol=C` on the command line (writer and pccheck); on FAT, pccheck lists unreadable files instead of failing. New ISOs doors-pcfat.iso / doors-pcfatcheck.iso.
- tools/powercut.py: FAT runs (`--fat-runs`, default 5). fsck.fat -n findings parsed into a set (any unknown line fails), must equal DOORS's mount-check findings; mtools checks the operation model.
  - The first 12 runs: 7 matched, 5 failed only on the parser ("Using first FAT." continues "FATs differ"). Then 30 of 30 matched: dirty, fatdiff, long, free + short, lost counts up to 59.
  - Shared clusters (a rename's window) and bad clusters never came up at random.
- Planted case for those (tools/mkdisk.py `damage_e` on E:, FAT12): LONG/SHORT/FREE/SHARE files, a lost cluster in FAT 1 only, the dirty flag. fsck.fat and DOORS matched line for line, cluster numbers and byte counts included.
  - BAD.TXT (a chain starting with 0xFF7) was dropped: fsck.fat 4.2 aborts on it ("Internal error: next_cluster on bad cluster"), so there is nothing to compare. DOORS reports it.
  - check_disk.py now holds the two parsers (fsck_findings, doors_findings; powercut imports them), expects E_DAMAGE on E: from both, takes `--log`. C: and D: must still be clean.
- tests/fsfuzz: DeAllocPage stub, fat_unmount at the end of the workload.
- First full run: `make test` PASS but CHECK_DISK FAIL on E:. fsck.fat found new damage: `share /E12.BIN`, `long /FREE.TXT`. DOORS's own FAT12 write test (selftest E12.BIN, 1 MB) had been given cluster 5, which the FAT called free but FREE.TXT still pointed to: the two files were now cross-linked.
  - **Decision:** a volume whose check finds a chain reaching a free/bad cluster, or shared clusters, is mounted **read-only** until repaired (`chk.unsafe`, `fat_check` returns it, kernel/fat.c fat_mount). Writing to it can join or destroy files. Longer/shorter chains, lost clusters and differing FAT copies only waste space or cut a file short, so those volumes stay writable (Linux mounts all of them rw; Windows runs chkdsk first).
  - kernel/vol.c: the `Volume` line says `(read-only)` for any file system now.
  - The planted damage is split: E: keeps the harmless kinds (LONG, SHORT, a lost cluster in FAT 1 only) and stays writable for the FAT12 write test. The unsafe kinds (FREE, SHARE) moved to a new FAT12 partition **H:** on disk 2 (GPT, after G:, Microsoft basic data type). mkdisk: `damage_fat12(img, tmp, unsafe)`, gpt_disk takes a partition list. check_disk: E_DAMAGE / H_DAMAGE, and "DOORS mounted H: read-only".
  - That `make smoke` run failed while the version bump was rebuilding the kernel during the runs. Rerun on the final tree: 24 PASS / 1 deferred.
- Results on the final tree: `make test` PASS + CHECK_DISK PASS, `make smoke` 24 PASS / 1 deferred, `make powercut` 10/10 (5 ext4, 5 FAT; FAT run 3 left a free cluster in a chain, so C: came up read-only and pccheck still read every file), `make fuzz` FUZZ PASS (9,000 images).

## ROADMAP step 1.6: an ext4 system disk (1.7.0, M8b done)
- Committed 1.6.0 as a0d2159 (tag v1.6.0, main fast-forwarded) first.
- Only grub-mkimage is installed (no grub-install / grub-bios-setup), and WSL has no loop devices, so GRUB goes on the image by hand:
  - core.img = `grub-mkimage -O i386-pc -p '(hd0,msdos1)/boot/grub' biosdisk part_msdos ext2` (26 KB), at LBA 1. grub-mkimage writes core's own sector count into diskboot's block list, and its default start (LBA 2) fits core at LBA 1.
  - MBR = boot.img with core's LBA at 0x5C. All of /usr/lib/grub/i386-pc/*.mod and *.lst go to /boot/grub/i386-pc on the ext4 volume, so `normal` and its dependencies load from the prefix.
  - **Found:** the first try ended at "error: no such partition" in grub rescue. boot.img's floppy-probe code runs past 0x1BE: copying all 512 bytes put code bytes into partition entries 2–4 (boot flag 0x84), and GRUB's msdos parser rejected the whole table. grub-bios-setup copies only 0..0x1B7; mkdisk does the same now.
  - GRUB 2.06's ext2 driver reads mkfs.ext4's default features (64bit, metadata_csum, flex_bg) and ignores needs_recovery, so a volume DOORS has mounted still boots.
- tools/mkdisk.py `--system ext4 --boot DIR` (make_sysdisk, SYS_PARTS): C: ext4 64 MB `DOORS-SYS` (boot\, DOORS\, MSAMPLES\, BIN\, HELLO.TXT), D: FAT16 16 MB. Makefile: build/sysdisk.img from the ISO's /boot tree, `make run-ext4`.
- ext4 is case-sensitive by design (selftest checks Case.txt vs case.txt), so the smoke test is adapted, not the file system:
  - The CLI ran commands as typed + ".ELF": `Service`, `TestSvc`, `busyloop` and `edit` would not find SERVICE.ELF etc. on ext4. user/progs/cli.c: `OpenRunFile` tries as typed, then upper-cased (header updated).
  - smoke64.py `--ext4`: boots `-boot c` with no ISO. B4 expects C: ext4 / D: FAT16. F9 expects `dir c:\msamples` to fail and `dir c:\MSAMPLES` to work. New B8: e2fsck -fn on the written C: is clean, EDITED.TXT and SMOKE are there, and the disk boots again.
  - First run: 24 PASS / 1 deferred, then 25 with B8. `make smoke` now runs both variants (~3 min).
- Also fixed: since 1.6.0 mkdisk planted E:'s damage in every disk, including build/disk.img for `make run`/doors.bat. It is now behind `--damage`, which only `make test` passes.
- Results: `make smoke` FAT32 24 PASS + ext4 25 PASS (1 deferred each), `make test` PASS + CHECK_DISK PASS. No kernel source changed in this step.

## ROADMAP step 1.7: full volumes, empty files, the longest names (1.8.0, Stage 1 done)
- Committed 1.7.0 as bb50bef (tag v1.7.0, main fast-forwarded) first.
- New kernel call `GetVolSpace(drive, &vol_space)` through FILESYS (FS_SPACE, `space` in fs_ops): FAT counts free clusters, ext4 adds up the group descriptors. Monitor `df`. ext4_mount makes the in-memory superblock free counts exact (from the descriptors).
- kernel/selftest.c `test_full`: edge_names (0-byte file: read → ErcEOF, write 0, size 0, rename, ReadDir, delete; 12 names of 255 chars in the root, alike but for the end, so FAT makes ~1..~12 aliases; 256th char → ErcBadFileSpec; a path > MAX_PATH → ErcBadFileSpec), fill_root (D:, E: until ErcRootFull), fill_inodes (until ErcDiskFull), fill_volume (1 MB files until ErcDiskFull; size == bytes reported; empty files at 100 % until the directory can't grow; read-back; delete; free space and inodes back exactly).
- Found, in order:
  1. **Security bug:** `edge_names` hung FILESYS. gdb on the hung test (new `QEMU_TEST` hook + a wrapper adding -s; qemu_test logs to /tmp/doors-test-PID.log while it runs) showed fsys_task spinning: WaitMsg error 10 on `fs_exch` = 0x71716C71. A hardware watchpoint caught the writer: `build_spec` (kernel/fsys.c:128) memcpy'd a drive-qualified path of any length into `static char spec[MAX_PATH]`, and the 264-byte test path ran into fs_exch. Kernel callers and direct `Request`s to FILESYS (any program can send one) reach it unchecked; only the system calls checked the length. Fix: `build_spec` refuses len >= MAX_PATH.
  2. Long names in the root grow the directory (21 entries each), and directories never shrink: free space is compared over a second pass, which must reuse the freed entries exactly.
  3. Inode fill on F: (4,000 creates) took ~42 ms per create: each is a journal commit of ~12 blocks through ATA PIO. Moved to a new small volume **I:** (disk 2, 16 MB, 4K blocks, -N 128; disk 2 grows to 64 MB).
  4. C: fill ran 7 s/MB: fat_write wrote sector by sector, and each new 512-byte cluster cost 4 FAT sector writes (both copies, entry + link), each with a cache flush. Fixes: whole sectors go out in runs (`wr_n`, up to 64); FAT sectors wait in a queue (`fq`, 32 sectors) and go out once each at the end of the operation (`fx_*` wrappers) and before any directory entry write (`dir_write`), so an entry never points into clusters the FAT calls free. A cut before the flush now leaves the file as it was. fat_truncate's grow zeroes only the old last cluster's tail (new clusters come zeroed).
  5. Full-disk correctness, from reading the code before the fill could show it: fat_write returned at a failed grow with the new clusters linked but the size not updated (fsck: chain longer). Now it writes what the chain holds, updates the size, frees the rest (`cut_chain`), and returns ErcDiskFull with the true count. ext4: a data balloc followed by a failing extent split would leave blocks allocated but in no tree; a failing split one level up would leave a written but unreferenced sibling. Now: `DATA_RESERVE` (8 blocks) kept from data, `tx.clean_stop` for a clean full stop (committed, partial), and **rollback** of any other failed operation (`tx_end_rb`: drop the transaction, restore e->sb from `tx.sb_save`; j_write/j_truncate restore size/done).
  6. KVM: /dev/kvm exists in WSL 2, but `make test` with -accel kvm was slower (nested virtualization: every PIO port access exits to Hyper-V). Not used.
- Timing: the fills take ~3 minutes through ATA PIO (~600 KB/s), so they run in a new **`make fulltest`** (cmdline "test full", 600 s timeout); the edge cases, root-full, inode-full and read-only checks run in every `make test` (`1.7: edge cases ok`). make test 128 s, make fulltest ~5 min.
- check_disk: e2fsck -fn on I:. The empty-files-at-100 % step exercises the ext4 rollback (ialloc succeeds, the directory block can't be had); inode counts come back exactly and e2fsck is clean.
- Version **1.8.0**. Stage 1 of the ROADMAP is complete. Docs: CHANGELOG, PROGRESS.md, devman 3 (df), 6 (full volumes), 10 (fulltest, QEMU_TEST), 11 (limits); ROADMAP 1.7 ✅; CLAUDE.md (rollback, FAT queue, untrusted requests, fulltest).
