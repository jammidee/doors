## Log

### Scan
- Top-level folders: `OSSOURCE` (kernel), `CM32` (C compiler + libc), `DASM` (assembler/linker),
  `MSCODE16` (16-bit DOS tools), `MMSYS` (system dir), `MSAMPLES` (apps), `fp32` (later math lib).
  About 58K lines of C and ASM.
- `fp32` won't build as-is: its includes are hardcoded to `c:\cm32\inc\...`, and it needs `MJOB.H` plus its own headers.

### 64-bit feasibility and plan
- The kernel depends on 32-bit-only features: hardware TSS task switching (`JMP FWORD PTR [TSS]`,
  `KERNEL.ASM:633`), GDT call gates for every syscall (`MPUBLICS.ASM`, more than 1,000 `CALL FWORD PTR` sites),
  and 2-level paging. CM32 and DASM can only produce 32-bit code.
- Result: a staged re-implementation in a new `port64/` tree (GCC + NASM + Multiboot2), not a
  conversion. Phases 0–9 are in `docs/PORT64_PLAN.md`.
- Possible original bug found: `__Request` reads `dData2` from `[EBP+20]`, the same slot as `dData0`
  (`OSSOURCE/KERNEL.ASM:546`). It should be `[EBP+12]`. Still to be checked against the book.

### Decisions (user)
- API names, parameters and error codes stay compatible. Only types widen.
- The file system will be modern. ext4 was chosen because host tools (`mkfs.ext4`, `e2fsck`) can build
  and verify images. The `MFILES.H` API is kept: names are already `(pName, cbName)`, so long names need no
  change, and sizes/offsets widen to 64-bit. A `ReadDir` call is added, and `DeleteDir` gets finished.

### Booting the original — problems found and fixed (in tools only; original files untouched)
1. **`MMURTL.IMG` is not a disk image.** It's the 160 KB in-memory OS image that the boot sector loads from
   cluster 2 onward (320 sectors) of a FAT12 1.44 MB floppy. → `tools/boot32/mkfloppy.sh` builds that floppy.
2. **The shipped `BOOTSECT.IMG` is a bad/different build.** It has `nBytesPerSect = 2000h`, and its code doesn't
   match `BOOTBLOK.LST`. → The boot sector is now taken from the 512 bytes of code in `BOOTBLOK.EXE` (after its
   512-byte header), which matches the listing.
3. **Boot signature.** `BOOTBLOK.ASM` deliberately ends with `BootSig DW 0AA5Fh`, and SeaBIOS refuses it.
   → The floppy builder writes `55 AA`.
4. **File system init fails without a hard disk.** HardIDE returns Erc 655 (`ErcNoDrive0`), then `InitFS` /
   `read_PE` returns Erc 505 (`ErcNoDriver`). → `tools/boot32/mkhdd.sh` builds a 29.5 MB IDE disk:
   16 heads × 63 sectors × 60 cylinders, one active FAT16 (type 04h) partition at LBA 63, holding `MMSYS` and
   `MSAMPLES`. The MBR entry is written by hand, without sfdisk.
5. **The shipped `MMURTL.IMG` is an older kernel.** It has a 1991–1993 copyright, no LPT driver, and prints
   "Erc1 from FDD". Its LoadCLI failed with Erc 668 (`ErcBadCmd`, IDE abort). → `tools/boot32/mkimg.py`
   (a Python port of `MAKEIMG.C`: data padded to 64 KB, then code padded to 96 KB) builds the image from
   `MMSYS/MMURTL.RUN`, which matches the shipped source.
   - An image from `OSSOURCE/MMURTL.RUN` differs from the shipped `MMURTL.IMG` in about 108K bytes. The two
     `MMURTL.RUN` files (MMSYS vs OSSOURCE) also differ, and the MMSYS one is used.

### Result
- `tools/boot32/run.sh` boots QEMU (`qemu-system-i386`, 16 MB, floppy A: + IDE C:) in a WSLg window,
  with a monitor socket at `/tmp/mmurtl.mon`.
- `tools/boot32/qscreen.py` reads the 80×25 VGA text screen from `0xB8000` through the monitor and can
  send keys. It's used for scripted checks.
- Observed:
  - The Monitor shows "BootDrive: A", 16384 KB total / 15736 KB free memory.
  - KBD, serial, LPT, floppy, HDD and file system all init with Error 0.
  - `A: FAT12` and `C: FAT16` are detected.
  - F1 (LdCLI) gives "Loading: A:\MMSYS\CLI.RUN... New CLI Job Number is: 3".
  - CLI `dir` lists A:\MMSYS; `dir c:\` lists volume `MMURTL`, `MMSYS` and `MSAMPLES`.
